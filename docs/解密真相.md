## 1. 解密是什么（一句话）

不是 AES、不是 RSA、不是逆向 exe。就是一条 **XOR 流密码（密文反馈）**：

```
P[i] = C[i] ^ C[i-1] ^ K[i % 512]

C[-1] = 0（每条 UDP 记录独立重置）
K      = 512 字节循环表
P      = 明文（还原后即标准 UE4 引擎包）
C      = 密文（网卡上抓到的）
```

**根本不需要 root、不需要偷密钥、不需要逆向 exe**。K 表要么已有现成的，
要么直接从裸抓包自动恢复。

## 4. K 表（512 字节）怎么来

### 方式 A：已知表（最直接）

如果手里有现成的表文件（`.bin` / `.hex` / `.json`），直接加载：

```python
from s2c_dec import load_table, decode_s2c
K = load_table("table.bin")           # 512 字节原始表
plain = decode_s2c(ciphertext, K)     # 去混淆
```

安卓端对应：`ParserBridge.loadTable(bytes)`（JNI 加载 512 字节表）。

### 方式 B：自动恢复（无需任何预置表）

`recover_table(datagrams, min_count=8)` 从裸抓包恢复：

原理——因为 `K[i%512] = C[i] ^ C[i-1] ^ P[i]`，对每个位置 i 收集大量
数据报的 `(C[i] ^ C[i-1])` 值，取众数。引擎包明文 P 在固定位置有大量
固定字节（0 / 协议头），所以众数投票能收敛出正确的 K 值。

**前提**：需要足够多的真实密文样本（几百到上千条 UDP 记录）。
**这不需要 root**，VpnService 抓包就能拿到大量密文。

安卓端对应：`ParserBridge.recoverTable(blob, lengths, minCount, maxLen)`。

## 5. 完整数据流（正确版）

```
VpnService 抓 UDP 密文
        │
        ▼
s2c_dec.decode_s2c()          ← XOR 流密码去混淆（无需 root）
        │  P[i] = C[i]^C[i-1]^K[i%512]
        ▼
标准 UE4 引擎包（明文）
        │
        ▼
codec.engine_packet.decode_engine_packet()   ← 剥外层帧
        │
        ▼
codec.engine_bunch.decode_engine_bunches()   ← 解 bunch 流
        │
        ▼
codec.bitstream / repdec4 / repdec6 / ...    ← 位流解码
        │
        ▼
playerstate_protocol / er_live 等            ← 提取玩家坐标/装备
        │
        ▼
WebView 雷达页显示玩家位置
```
